# Manuscript and Reproducibility Guide

This repository contains the analysis code and result files for the study. The manuscript is not included. The reproducibility package is reproducibility_package_code_results.zip. Raw market-price data are not included; the scripts retrieve data through Yahoo Finance, so results may vary if the provider revises its data.

> **Important:** This is a local working and submission-preparation folder. The manuscript and outputs are not all included in the public code archive. Before journal submission, check the journal's current instructions, confirm author and affiliation details, and provide the final public archive link and DOI where required.

## 1. The research question

The study asks whether a Bayesian LASSO model that changes its coefficient shrinkage according to market regime and feature evidence improves five-day equity-return forecasts.

The comparison is designed to separate two ideas:

1. A model may improve because it fits a different regression in each regime.
2. A model may improve because its proposed data-dependent shrinkage weights are useful.

For a fair comparison, the experiments include pooled models, pooled LASSO with regime interactions, regime-specific LASSO and Bayesian LASSO, and Bayesian prior ablations. Simulation data also have a known coefficient structure, which lets the analysis measure feature recovery as well as forecast error.

The conclusion is deliberately cautious. The method does not show a reliable real-market forecasting advantage. The paper reports that result directly; the simulations identify a modest feature-recovery benefit in one small, noisy setting, not a general improvement.

## 3. The analysis in plain language

The program follows a chronological prediction workflow:

1. **Build the data.** Download market observations and calculate predictor variables such as return, volatility, and technical indicators.
2. **Split by date.** Earlier dates are used to train the model. Later dates are reserved for validation or final evaluation.
3. **Purge boundary dates.** The response is a five-day return, so adjacent observations overlap. The scripts remove five trading dates near split boundaries to reduce overlap leakage.
4. **Estimate market regimes using training data.** The hidden Markov model (HMM) is fit within the training split. Held-out regimes are assigned with forward-filtered probabilities from that training fit.
5. **Fit every competing predictor.** Baseline and proposed models use the same split and forecast rows. Hyperparameters are selected on validation data, not on the final test outcomes.
6. **Score predictions.** The scripts save predictions and calculate error measures, benchmark-relative scores, and paired forecast-comparison tests.

In the simulations, regime labels and true active predictors are known by construction. This allows the code to check both prediction accuracy and whether models identify the active predictors. Each repeated simulation setting has 30 replications. This is controlled evidence for the specified designs, not proof that the method works for every possible market or data-generating process.

## 5. Rebuilding the manuscript

The current source is set up for the Springer Nature `sn-jnl` class with author-year citations and an alphabetized reference list, consistent with the *Computational Economics* instructions. The reference list is manually written in the TeX file, so BibTeX is not required.

### Compile from a terminal

Install a LaTeX distribution such as MiKTeX or TeX Live, then run these commands from this folder:

```powershell
pdflatex springer_manuscript.tex
pdflatex springer_manuscript.tex
```

The second pass updates cross-references and the table of contents. The manuscript uses figures from `figures/`, so compile from this directory or preserve the relative folder structure. In the Codex desktop editor, use its compile command for `springer_manuscript.tex` to check diagnostics and update the preview.

### What to check after compilation

- Confirm the PDF opens and the title, abstract, tables, equations, and figures render.
- Check the LaTeX log for errors, undefined references, missing files, and unresolved citations.
- Confirm every figure and table is cited in the text and appears in numerical order.
- Recheck page breaks and table widths after substantive edits.
- Confirm that the PDF was produced from the latest saved `.tex` file.

## 6. Rebuilding the analysis

The code and saved results are in `reproducibility_package/`. From PowerShell, one possible setup is:

```powershell
Set-Location .\reproducibility_package
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r .\important_code\requirements.txt
```

Then read `important_code/PLAIN_LANGUAGE_ANALYSIS_GUIDE.md` for the detailed execution order. The high-level sequence is:

1. Build or download the market features with `First.py`.
2. Tune real-data settings using `tune_bayesian_lambda0.py`.
3. Run the primary fixed-split analysis with `robust_real_data_validation.py`.
4. Run the simulation tuning and repeated simulation scripts.
5. Run the rolling-window, multi-year tuning, and sector ETF analyses.
6. Run the paired forecast tests and rolling block bootstrap after the prediction and yearly result files exist.
7. Run the MCMC diagnostic script when reproducing the diagnostic table.

Some scripts depend on outputs created by earlier scripts. Running everything in a different order may fail or use stale files. Check each script's input/output paths before rerunning a single stage.

### Data and exact reproducibility

The reproducibility package includes result files but does not bundle raw vendor-supplied market price data or all row-level prediction data. The data-building scripts retrieve market observations through `yfinance`. The provider can revise historical prices, ticker coverage, and adjusted data, so a fresh download can produce small differences from archived results. Follow the provider and data-source terms, especially before redistributing downloaded observations.

For auditability, use the saved CSV outputs to inspect the specific results reported in the manuscript. To regenerate results exactly, preserve the data snapshot, software versions, random seeds, and configuration files associated with a run. The project does not currently provide a fully locked environment file with exact package versions.

## 7. Important interpretation notes

- **Lower RMSE and MAE indicate smaller errors.** Do not interpret small numeric differences as meaningful without the paired comparison results.
- **Benchmark-relative (R^2)** uses the appropriate historical training mean, not the mean of future test outcomes.
- **Simulation feature-recovery scores** are available because the simulated active predictors are known. Real-market predictive performance is the main empirical test.
- **The full method is data-dependent.** Its weights are calculated from training data; describe them as empirical-Bayes or data-dependent weights rather than fixed external prior information.
- **Regime labels are descriptive labels.** They are estimated latent states, not directly observed economic facts.
- **A nonsignificant test is not proof of equality.** Report the estimate, uncertainty, test family, and adjustment method together.
- **The current equity universe may have survivorship limitations.** The results should not be presented as an unbiased market-wide estimate unless the sample construction supports that claim.
